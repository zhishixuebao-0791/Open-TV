# 授权状态与源码发布边界

核查日期：2026-11-17。

## 为什么暂不上传完整应用源码

Open TV 的本地改造代码基于 [hxh19950701/WebViewTvLive](https://github.com/hxh19950701/WebViewTvLive) 的历史工程。核查发现：

- 本地工程没有项目级 `LICENSE`；资源目录中的 HLS.js 授权文件只适用于相应第三方组件。
- GitHub 仓库元数据的 `license` 为 `null`；已递归核对的当前 `main` 和历史 `1.2` 标签没有找到项目级 LICENSE、COPYING 或 NOTICE。
- [上游简体中文 README](https://github.com/hxh19950701/WebViewTvLive/blob/main/README_CN.md) 写有源码学习交流、二次打包适度分享及非牟利限制。
- 维护者未另行取得原作者明确允许公开再分发修改后源码的授权。

以上不足以确定可以对整个衍生项目授予 MIT、Apache-2.0 或 GPL 等标准开源许可。因此当前不上传继承的应用源码、图像资产和 APK，不宣称应用已经完成开源。

这是当前证据下的发布决定，**不是对任何法院裁判、全部历史提交或上游权利范围的法律结论**。没有穷尽上游每一条历史提交；如能提供适用于本地所用代码版本的有效许可或权利人授权，可以据此重新核对。

[GitHub 的许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)区分了公开仓库与开源授权；[Choose a License 的无许可证说明](https://choosealicense.com/no-permission/)也说明仅能查看或 fork 不等于获得通常开源协作所需的全部权利。

## 后续解除条件

发布完整代码前，需要明确以下范围：

1. 原作者或相关权利人允许公开发布所用版本及其修改后的源码。
2. 明确可以采用的许可证、必须保留的署名和其他条件；不能把“允许分享安装包”直接当作“允许任意再授权源码”。
3. 独立核对继承图片、脚本和各第三方依赖的许可及必要声明。
4. 去源候选版通过隐私审查、构建及与其改动相称的验证，然后从干净历史发布；不带入私人历史文件。

另一条可选路线是基于授权清楚的基础重新实现，但这属于单独的开发工作，当前并未完成，也不把现有代码换名视为重新实现。
